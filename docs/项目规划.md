## 1. 已确认的技术决策

| # | 决策项 | 结论 | 理由 |
|---|---|---|---|
| D1 | 起步方式 | **先完成 S0 设计文档，再开始编码** | 数据库和接口先定死，V1.1/V1.2 不需要返工改表 |
| D2 | 代码分工 | 业务代码由作者实现；AI 助手在**被点名时**实现指定模块、评审代码 | 练习项目，写代码本身就是目的 |
| D3 | 前端工程结构 | **三个独立 Vue 2 工程 + 根目录统一脚本** | 与 V2.0 三个 OIDC Client 一一对应，SSO 验证最直接 |
| D4 | 大语言模型 | **DeepSeek**（OpenAI 兼容协议） | 国内直连、价格低、兼容 `openai` SDK，便于切换 |
| D5 | Embedding 模型 | **本地 `BAAI/bge-small-zh-v1.5`**（sentence-transformers，512 维） | ⚠️ DeepSeek 官方**不提供 Embedding 接口**，必须单独选型；本地模型零成本、可离线 |
| D6 | 分类字典 | **一级分类系统预置固定 + 允许用户自定义二级子类** | 统计口径稳定，同时保留灵活性 |
| D7 | 分类存储 | 独立 `categories` 表 + 版本内 seed，代码常量只做「系统分类不可删」校验 | 避免 enum 硬编码后无法扩展子类 |
| D8 | 角色模型 | **`users.role` 三值枚举（user/vip/admin），不建 roles 表** | 角色集合固定且与 Keycloak realm role 一致，避免双份数据源 |
| D9 | 认证抽象 | V1.2 起校验逻辑收敛为**唯一依赖 `get_current_user`** + `TokenVerifier` 抽象 | V2.0 换成 Keycloak JWKS 时零接口改动 |
| D10 | 时区策略 | 数据库统一存 **UTC**；应用层单点转换；API 返回带 `+08:00` 偏移的 ISO8601 | 「本月」「明天下午三点」等自然语言时间必须有唯一基准 |
| D11 | 软删除 | 个人业务表统一 `deleted_at` 标记，查询默认过滤 | 便于审计与误删恢复，避免级联物理删除 |
| D12 | UI 组件库 | **Element UI**（Vue 2 生态最成熟） | 表单/表格/分页直接可用，节省大量样式工作量 |
| D13 | 前端构建 | **vue-cli 5 + Node 18 LTS**（不用 Vite） | Vite 对 Vue 2 需额外插件、坑较多；练习项目求稳 |
| D14 | 后台任务 | **APScheduler 进程内调度**（V1.3 起），队列落 `async_tasks` 表 | 单机部署无需 Celery/Redis，后续可平滑替换 |
| D15 | 缓存与配额 | **先不引入 Redis**，配额用 `ai_usage_logs` 计数表 + 每日窗口查询 | 减少一个中间件；数据量小，性能足够 |
| D16 | Python 运行环境 | **`backend/.venv`，Python 3.11.17**，解释器取自 conda `langchain` 环境 | 系统 Python 是 3.14，`pydantic-core` 等无预编译轮子；`conda create --clone` 被 Anaconda ToS 拦住，改用 venv 同样隔离且不污染学习环境 |
| D17 | MySQL 账号 | 开发期直接用 `root`，密码只写 `backend/.env`（已 gitignore） | 练习项目简化；上生产前换专用账号 |

### 1.1 因决策产生的勘误（相对原需求文档）

| 原文档表述 | 实际情况 | 处理 |
|---|---|---|
| 待办/生活记录包含「饮水」 | 核心数据实体清单中**没有**饮水表 | 新增 `water_records` 表 |
| V1.4 才增加购物模块 | V1.1 已有 `add_shopping_item` 工具、9.1 流程要求写入购物清单 | `shopping_lists`/`shopping_items` **建表提前到 V1.1**，页面仍按 V1.4 交付 |
| 写入型操作需用户确认 | 未定义草稿存储与确认接口 | 新增 `ai_pending_actions` 表 + 幂等键机制（见 AI 设计） |
| 用户 ID 必须后端注入 | 未提时间基准注入 | 工具上下文同时注入 `now`/`timezone`/分类字典 |
| 管理后台需配置模型、查看调用量 | 无对应数据表 | 新增 `ai_model_configs`、`ai_usage_logs` |
| 文档解析需后台任务与进度 | 无任务表 | 新增 `async_tasks`（通用任务表） |
| 管理员不得访问私人知识库 | 仅为原则性要求 | 后台接口不接受 `user_id` 查询私人文档，技术层面禁止 |
| V1.2 只有 user/admin | README 4 节把 `vip` 列为角色 | V1.2 建全三值枚举，`vip` 至 V2.0 才启用 |
| 测试在 V1.4 补充 | 数据隔离测试应在加多用户时就建立 | **数据隔离测试随 V1.2 建立** |

## 4. 风险登记

| 风险 | 等级 | 处理方式 |
|---|---|---|
| **Vue 2 / Vue Router 3 已 EOL** | 中 | 锁 `Vue 2.7.16` + `vue-cli 5` + `Node 18 LTS`；不追求新工具链；已知悉无安全补丁 |
| DeepSeek 无 Embedding 接口 | 中 | 已选本地 bge-small-zh；需额外 `torch` 依赖（约 2GB），或退化为调用第三方 embedding API |
| **Milvus 多租户隔离** | 高 | `partition_key=user_id`；过滤条件由后端拼接，模型不可传入 `user_id` |
| Milvus 无行级权限，删除需 delete-by-expression | 中 | 删除走软删 + 补偿任务，失败可重试 |
| MySQL/文件/Milvus 三处一致性 | 中 | `async_tasks` 记录清理任务，失败重试 3 次后告警 |
| LangChain 版本破坏性变更 | 中 | 锁定版本；封装 `ai/` 薄适配层，业务代码不直接依赖 LC 类型 |
| LLM 结构化输出不稳定 | 中 | Pydantic 校验 + 重试 2 次 + 失败降级为可读提示；分类用 enum 约束 |
| Vue 2 + npm 依赖冲突 | 中 | 使用 `--legacy-peer-deps`；锁 `package-lock.json` |
| 项目周期长导致动力衰减 | 中 | 按版本暂停；每版都可独立运行演示 |
| AI 调用费用 | 低 | `ai_usage_logs` 统计 + 每日配额；DeepSeek 单价低 |

## 5. 协作方式

1. **文档先行**：任何表结构或接口变更，先改 `docs/` 下对应文档，再改代码。
2. **代码分工**：作者实现；AI 助手在被点名时实现指定模块或做代码评审。
3. **验收驱动**：每版本结束按 `需求规格说明书.md` 对应小节逐条打勾，再进下一版。
4. **提交规范**：`feat|fix|docs|refactor|test|chore(scope): 说明`，见 `docs/工程规范.md`。
5. **单一来源**：需求以规格书为准，执行以本文档为准，README 只保留概览与入口链接。
