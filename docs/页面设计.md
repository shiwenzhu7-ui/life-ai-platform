### 1.3 首页线框图（V1.0）

首页是唯一跨模块的页面：左侧待办数字与列表来自 `tasks`，右侧消费数字与柱状图来自 `expenses`。
后端用一次 `GET /dashboard/overview` 全部返回（对应 `docs/接口设计.md` §7），前端不并发二次请求。
「逾期与今日到期」是**混排**列表——逾期的最多自动排在最前，`due_at` 升序，最多 5 条，每条带 `is_overdue`。

```text
┌──────────────────────────────────────────────────────────────────┐
│ 首页仪表盘                                     2026-11-02 星期日 │
├──────────────────────────────────────────────────────────────────┤
│ 早上好，演示用户                                                 │
│                                                                  │
│ ┌──────────────────────────────┐ ┌─────────────────────────────┐ │
│ │ 待办概览                     │ │ 本月消费                    │ │
│ │ 未开始 5   进行中 2          │ │ ¥ 1,280.50                  │ │
│ │ 已完成 12  逾期 2            │ │ 上月 ¥990.00                │ │
│ │ 今日到期 3                   │ │ 今日 ¥88.00                 │ │
│ │                              │ │                             │ │
│ │ ▸ 查看待办                   │ │ ▁▂▅▃▇▂█  近 7 天            │ │
│ └──────────────────────────────┘ └─────────────────────────────┘ │
│                                                                  │
│ 逾期与今日到期（最多 5 条）                           ▸ 查看全部 │
├──────────────────────────────────────────────────────────────────┤
│ ! 写周报                  今天 18:00          逾期 2 天          │
│   交房租                  11-03 09:00         明日到期           │
│   买菜                    今天 20:00          今天到期           │
│                                                                  │
│ [+ 新建待办]   [+ 记一笔]                   跳 /tasks、/expenses │
└──────────────────────────────────────────────────────────────────┘
```

| 页面元素 | 接口 | 参数 / 字段 |
|---|---|---|
| 待办卡片四数字 | `GET /dashboard/overview` | `tasks.todo` `tasks.doing` `tasks.done` `tasks.overdue` |
| 今日到期数字 | 同上 | `tasks.today_due`：`现在 <= due_at < 明天 00:00`，与 `overdue` 不重叠，两者相加即列表候选条数 |
| 逾期与今日到期列表 | 同上 | `focus_tasks`：逾期与今天到期混排，`due_at` 升序，最多 5 条，每条带 `is_overdue` |
| 消费卡片三数字 | 同上 | `expense.current_month_total` `expense.last_month_total` `expense.today_total` |
| 近 7 天迷你柱状图 | 同上 | `recent_7d`：恒 7 个点（含今天），无数据的日期补 `"0.00"` |
| 快捷入口 | —— | 纯前端路由跳转，不调接口 |
| 空状态 | 同上 | 各项计数为 0、`focus_tasks: []`、`recent_7d` 全为 `"0.00"` |

**口径**：「今日」与「本月」都按北京时间算，用半开区间（`[今天 00:00, 明天 00:00)`、`[本月 1 日 00:00, 下月 1 日 00:00)`），与消费页汇总同一套换算；金额一律两位小数的字符串；`focus_tasks` 的 `is_overdue` 由服务器时间判断，前端不自己算。

### 1.4 待办页线框图（V1.0）

列表 + 筛选条 + 右侧抽屉，对应 `docs/接口设计.md` §4 的 6 个端点；
`分类` 一列依赖 `categories` 模块（V1.0 只读接口），其余全部由 `tasks` 模块提供。

```text
┌──────────────────────────────────────────────────────────────────┐
│ 待办事项                                            [+ 新建待办] │
├──────────────────────────────────────────────────────────────────┤
│ 状态 [未开始] [进行中] [已完成] [已取消]   分类▾  优先级▾  日期▾ │
│ 🔍 搜索标题 / 描述                                               │
├──────────────────────────────────────────────────────────────────┤
│ ☐  买牛奶和鸡蛋          ●高    购物     10-31 15:00         ✏ ✕ │
│ ☑  写周报                ●中    工作     10-30 18:00 逾期    ✏ ✕ │
│ ☐  取快递                ●低    ——       ——                  ✏ ✕ │
├──────────────────────────────────────────────────────────────────┤
```

新建 / 编辑从右侧滑出抽屉（宽度 420px），字段与 `TaskCreate` 一一对应，
保存时只提交改动过的字段（`PATCH` 语义）：

```text
              ┌────────────────────────────────────────────┐
              │ 新建待办 / 编辑待办                        │
              ├────────────────────────────────────────────┤
              │ 标题*     [____________________]           │
              │ 描述      [____________________]           │
              │ 分类      [ 未分类 ▾ ]                     │
              │ 优先级    ○低   ◉中   ○高                  │
              │ 截止时间  [2026-10-31 15:00  ]             │
              ├────────────────────────────────────────────┤
              │                             [取消]  [保存] │
              └────────────────────────────────────────────┘
```

| 页面元素 | 接口 | 参数 / 字段 |
|---|---|---|
| 列表 + 分页器 | `GET /tasks` | `page` `size` `sort` |
| 筛选条 | `GET /tasks` | `status`（多值）`category_id` `priority` `due_from` `due_to` `keyword` |
| 逾期标红 | `GET /tasks` | 响应字段 `is_overdue`（按服务器时间计算） |
| 复选框切状态 | `PATCH /tasks/{id}/status` | `status` |
| 行内编辑 | `GET /tasks/{id}` + `PATCH /tasks/{id}` | 只传改动字段；`due_at: null` 表示清空 |
| 行内删除 | `DELETE /tasks/{id}` | 硬删除（行消失、不可恢复），二次确认后调用 |
| 新建 | `POST /tasks` | `title` `description` `category_id` `priority` `due_at` |
| 空状态 | `GET /tasks` | 返回 `items: []`，前端渲染引导按钮 |

| 页面元素 | 接口 | 参数 / 字段 |
|---|---|---|
| 月份切换 + 三个数字 | `GET /expenses/summary` | `month=2026-11`，不传默认当月 |
| 类别占比横向条 | `GET /expenses/summary` | 响应 `by_category[].total` / `ratio` |
| 列表 + 分页器 | `GET /expenses` | `page` `size` `date_from` `date_to` |
| 筛选条 | `GET /expenses` | `type` `category_id` `keyword` |
| 记账保存 | `POST /expenses` | `type` `amount` `category_id` `account` `occurred_at` `tags` `note` |
| 行内编辑 | `GET /expenses/{id}` + `PATCH /expenses/{id}` | 只传改动字段；`note: null` 表示清空 |
| 行内删除 | `DELETE /expenses/{id}` | 硬删除（行消失、不可恢复），二次确认后调用 |
| 分类九宫格 | `GET /categories?scope=expense` | 切换类型时换 `income` |
| 空状态 | `GET /expenses` | 返回 `items: []`，渲染「还没有记账，记一笔」 |

**金额口径**：请求用数字或字符串均可，响应恒为字符串（`"1280.50"`），两位小数；
支出记正数、方向由 `type` 表达，前端按 `type` 决定显示红/绿与正负号。

**账户只记录、不筛选**：`account` 是每条账的字段（列表里显示、记账弹窗里可选），
但不作为筛选维度——筛选条只有关键词 / 类型 / 分类 / 日期四项，对应
`docs/接口设计.md` §5 与 `GET /expenses` 的五个筛选参数。

### 1.6 页面要点

**首页仪表盘（V1.0）**
- 待办卡片：未开始/进行中/已完成/逾期 四数字 + 今日到期列表。
- 消费卡片：本月支出、上月支出、今日支出、近 7 天迷你柱状图。
- 快捷入口：新建待办、记一笔。
- 数据来源：`GET /dashboard/overview`。

**待办页（V1.0）**
- 顶部筛选条：状态（多选标签）、分类、优先级、日期范围、关键词搜索。
- 列表：复选框切状态、标题、分类标签、优先级色点、截止时间（逾期标红）、行内编辑/删除。
- 新建/编辑：右侧抽屉，字段同接口校验。
- 空状态：插画 + 「还没有待办，新建一个」按钮。

**消费页（V1.0）**
- 顶部：月份切换器 + 本月支出/收入/结余三个数字。
- 中部：类别占比横向条（ECharts 于 V1.4 换成饼图）。
- 列表：日期、类别、账户、金额（支出红/收入绿）、备注。
- 记账弹窗：类型切换（支出/收入）、金额大字输入、分类九宫格、账户、时间、标签、备注。

**AI 助手页（V1.1）**
- 左侧：会话列表（新建、重命名、删除）。
- 右侧：消息流 + 输入框（Enter 发送、Shift+Enter 换行）。
- **确认卡片**：当 `pending_action` 存在时，在 AI 消息下方渲染结构化预览
  - 待办：标题、分类、优先级、时间
  - 消费：金额、分类、账户、时间
  - 底部「确认保存」/「取消」两按钮，确认时按钮进入 loading 并禁用，防重复提交。
  - **已实现（V1.0 / A5 第 6 步）**：`components/PendingActionCard.vue`，目前只支持待办一种。
    卡片随消息一起从 `GET /ai/sessions/{id}/messages` 带回（`pending_action`），
    所以刷新页面后原样恢复；已确认/已取消/已过期显示成灰卡 + 状态文字，按钮消失。
    消费的字段要等 `create_expense` 工具做出来再补，组件里已按 action_type 预留标题与图标映射。
- 引用展示（V1.3）：答案下方折叠「参考来源」，列出文档名 + 页码 + 片段。
- 生成中：三点打字动画 + 「AI 正在思考」文案（NFR：必须显示生成状态）。

**知识库页（V1.3）**
- 上部：拖拽上传区（限 pdf/docx/txt，20MB）；前端预检只拦明显不对的（扩展名、大小），真正的校验以后端为准。
- 列表：文件名、大小、状态徽标（待处理/解析中/切块中/向量化中/就绪/失败）、分块数、上传时间、删除。
- 处理中：轮询列表接口（2s），状态变了就地刷新那一行；V1.3 **没有**单独的任务进度接口。
- 失败：显示 `error_message` + 「重新处理」= 删掉重传（后端没有 reprocess 接口）。
- 删除：二次确认，文案写明**不可恢复**（硬删）。
- 空状态：一句话说明「上传 PDF / Word / 文本，之后在 AI 对话里可以直接问它们」。

> 引用卡片是这套功能的唯一价值出口：`/ai` 对话里命中知识库时，回答下方显示来源卡（文档名 + 页码 + 片段）。
> 知识库页本身只是「上传和看状态」，不提供阅读器。

| 页面元素 | 接口 | 约束 |
|---|---|---|
| 用户列表 | `GET /admin/users` | 分页；`keyword` / `role` / `status` 筛选 |
| 编辑抽屉 | `PATCH /admin/users/{id}` | 改 `status` / `role`（`daily_ai_quota` 已于 2026-11-10 取消） |
| 防降级 | `PATCH /admin/users/{id}` | 禁止把**最后一个**管理员降级（后端校验，返回 409） |
| 角色说明 | `GET /admin/roles` | 只读，返回三个角色的能力描述 |
| 明确禁止 | —— | 不存在任何「按 `user_id` 查私人日记/文档/对话」的接口 |

### 3.3 要点

- 所有页面路由守卫校验 `role === 'admin'`，非管理员跳 403 页。
- **不得出现**任何查看用户私人日记、私人文档、对话记录的入口。
- 用户管理：改状态（启用/禁用）、改角色；禁止把最后一个管理员降级。（调额度已于 2026-11-10 取消）
- AI 配置：只展示环境变量名，不展示密钥值。

## 4. 通用交互规范

| 场景 | 规范 |
|---|---|
| 加载中 | 首屏骨架屏；列表局部 loading 遮罩；按钮内联 spinner 并禁用 |
| 空状态 | 每个列表必须有插画 + 一句引导 + 主操作按钮 |
| 错误 | 表单字段下方红字；请求失败用顶部 message 提示（含 `request_id` 便于排查） |
| 删除确认 | 一律二次确认弹窗，显示对象名称 |
| 表单校验 | 失焦即时校验 + 提交前整体校验；必填项标红星 |
| 时间显示 | 相对时间（「3 分钟前」「明天 15:00」）+ hover 显示完整时间 |
| 移动端 | 断点 768px / 1200px；表格在窄屏转卡片列表 |
| 无障碍 | 表单 `label` 关联、按钮有 `aria-label`、颜色不作为唯一信息载体（优先级同时带文字） |
